Microsite Header Examples

Examples of microsite header components following the Alberta Design System. Communicate what stage the service is at, connect to Alberta.ca, and gather feedback on your service.

Basic Alpha Header

The most common microsite header for new services in early development. Includes feedback link and clear indication this is a new Alberta Government service.

Code:

<goab-microsite-header 
  type="alpha"
  (onFeedbackClick)="onFeedbackClick()">
</goab-microsite-header>

Beta Header

For services that are feature complete but still in testing phase. Shows beta status to set user expectations.

Code:

<goab-microsite-header 
  type="beta"
  (onFeedbackClick)="onFeedbackClick()">
</goab-microsite-header>

Live Header

For production-ready services. Minimal design without feedback prompts as the service is stable.

Code:

<goab-microsite-header 
  type="live">
</goab-microsite-header>

Header with Version Display

Shows version information on the right side. Useful for tracking releases and helping users report issues.

Code:

<goab-microsite-header 
  type="alpha"
  version="v1.2.3"
  (onFeedbackClick)="onFeedbackClick()">
</goab-microsite-header>

Header with Custom Feedback URL

Directs feedback to a specific URL instead of using the click event handler. Useful for external feedback forms.

Code:

<goab-microsite-header 
  type="beta"
  feedbackUrl="https://forms.microsoft.com/feedback"
  version="v1.2.3">
</goab-microsite-header>

Header with Custom Max Content Width

Constrain the header content to match your application's layout. Useful for maintaining consistent spacing with your main content.

Code:

<goab-microsite-header 
  type="alpha"
  maxContentWidth="800px"
  version="v1.2.3"
  (onFeedbackClick)="onFeedbackClick()">
</goab-microsite-header>

Header with Slotted Version Content

Use slotted content for more complex version display. This allows you to include custom HTML, styling, or additional information in the version area.

Version v{{ getCurrentVersion() }}

Code:

<goab-microsite-header 
  type="alpha"
  [version]="versionSlot"
  (onFeedbackClick)="onFeedbackClick()">
</goab-microsite-header>
<ng-template #versionSlot>
  <a href="#">Version</a>
</ng-template>

Header with Complex Slotted Version

More advanced slotted content example with detailed version information and custom styling.

v{{ getCurrentVersion() }} (Build: {{ getBuildNumber() }})

Code:

<goab-microsite-header 
  type="beta"
  [version]="versionSlot"
  (onFeedbackClick)="onFeedbackClick()">

Usage Guidelines

When to use different microsite header types:

  • Alpha: New services in early development stage - expect significant changes and gather lots of feedback
  • Beta: Services that are feature complete but still in testing - may have bugs, gathering feedback for improvements
  • Live: Production-ready services that are stable and fully tested

Best Practices:

  • Always include version information for alpha and beta services to help with issue reporting
  • Use feedback URLs to direct users to specific feedback forms or surveys
  • Match the max content width to your main application layout for consistency
  • Use appropriate link targets - external feedback forms should open in new tabs
  • Keep version numbers meaningful and follow semantic versioning when possible
  • Remove feedback prompts once your service moves to live status

Content Guidelines:

  • The header automatically includes "This is a new Alberta Government service" for alpha/beta
  • Feedback link text is automatically generated based on the type
  • Version information should be concise (e.g., "v1.2.3", "Beta", "UAT")
  • Keep feedback URLs focused on service improvement, not general government feedback

Technical Considerations:

  • The component handles responsive behavior automatically
  • Use event handlers for custom feedback tracking and analytics
  • Consider accessibility when choosing link targets and URLs
  • Test with different content widths to ensure proper alignment
